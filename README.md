## ✍️ AGILE PROJECT MANAGEMENT & RUBRIC EVIDENCE[cite: 4]

### 📜 1. Agile Team Charter
* **Evidence:** Established a co-created social contract defining our shared purpose, core values (transparency, accountability, collaboration), and working agreements across project workflows (such as Water Watch and WorkLink developments) to reduce friction and align daily execution[cite: 4].
* **Reflection:** Having a clear team charter kept everyone aligned from day one. It set clear behavioral boundaries and made resolving blockers much smoother since we all agreed on our communication protocols upfront.

---

### 📝 2. User Stories and Tasks
* **Evidence:** Features across Water Watch, WorkLink, and MediTrack were mapped out as user stories from the end-user perspective, then broken down into atomic tasks[cite: 4].  
  * *Example User Story:* "As a user, I want to view my monthly water usage statistics on an interactive graph so that I can track consumption patterns." -> *Tasks:* Design chart component, integrate state hooks, style dashboard grid.
* **Reflection:** Breaking requirements down into user-centric stories ensured that our development remained focused on delivering real value to the end user rather than just writing code for the sake of it.

---

### 🗂️ 3. Product Backlog
* **Evidence:** Maintained a prioritized master list of all required work, features, bug fixes, and improvements managed via Kanban boards[cite: 4].  
  * *High Priority:* Core dashboard architecture, responsive layouts, data state binding.  
  * *Medium Priority:* Advanced filtering, custom alerts, settings panels.  
  * *Low Priority:* Secondary visual animations, extended color themes.
* **Reflection:** The product backlog gave us a clear bird's-eye view of project scope. Prioritizing items early helped us manage scope creep and focus our energy on high-impact deliverables first.

---

### 🏃 4. Sprint Backlog
* **Evidence:** Created real-time, actionable sprint plans detailing specific tasks targeted for completion during iterative cycles (e.g., Sprint 1: Water Watch UI components; Sprint 2: WorkLink integration features)[cite: 4].
* **Reflection:** Sprint backlogs forced us to be realistic about our velocity. Breaking work down into short, time-boxed sprints helped us measure progress accurately and pivot quickly when technical roadblocks arose.

---

### 📖 5. Agile Logbook
* **Evidence:** Maintained an active tracking log documenting daily stand-ups, sprint planning sessions, and retrospective notes across development iterations[cite: 4].  
  * *Daily Stand-up Excerpt:* Reviewed component rendering states for Water Watch graphs; resolved prop-drilling issues.  
  * *Retrospective Note:* Improved Git branching workflows to streamline parallel feature development on multi-page applications.
* **Reflection:** Keeping a daily logbook transformed how we handled accountability. Looking back at retro notes allowed us to actively fix recurring workflow issues and improved team communication sprint over sprint.
